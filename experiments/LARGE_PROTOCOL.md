# Larger repository observation experiment

The dataset is generated by `large_fixture.py`: DispatchDesk, a synthetic
multi-tenant order and dispatch library with 95 Python files and 8,067 package
source lines (8,146 lines including public tests and README). Sixteen resource
families provide executable models, codecs, queries, and policy helpers. Pricing
and event-query modules also contain working report aggregations. Code generation
is deliberately regular; repository size is not evidence of real-world complexity.

The browsable known-good source repository is `large_v1/reference/`. Seeded
fixtures are in `large_v1/fixtures/{quote,cache,feed}/`. Each trial gets a full,
independent source copy under `large_v1/runs/<run_id>/work/`.

## Protocol fixed before launch

- Model: fresh `gpt-5.6-luna` native agents, low reasoning effort, no history fork.
- Three independent tasks, three observation modes, two repetitions: 18 trials.
- Full mode: whole-file reads, search, and file listing.
- Foveated mode: AST outlines, up-to-40-line regions, search, and file listing.
- Adaptive mode: all of the above, chosen freely with no outline-first rule.
- Identical literal search in all arms, capped at 30 matching lines, with optional
  path-prefix narrowing. Shared search is itself a targeted observation; this
  experiment tests the additional read choices, not targeted retrieval versus none.
- All start with the same protocol structure and task contract. No preloaded
  source, outlines, test failure, or task-specific file list.
- Shared exact-snippet replacement, requiring a unique match and syntactically
  valid Python. Base64 transports snippets through PowerShell. This removes the
  previous pilot's line-shift issue equally in all arms.
- Shared budget: 36 actions after `start`, plus mandatory `finish` verification.
- Same public tests and snapshot hashes within each task. Tests are read-only.
- A held-out suite was defined and validated before any agents were launched.
  It is absent from candidate workspaces and inaccessible through the interface.
- Golden code passes public and held-out suites. Every defect fixture fails both.
- No pruning, editorial pass, sleep engine, parent guidance, or inter-agent sharing.
- Up to three agents execute concurrently. Trial launch order rotates modes
  across task groups; it is balanced in counts but not statistically randomized.

The exact launch prompt and interface protocol for each trial are saved alongside
its state. Native agents are instructed to use only the interface; this is not
OS-level isolation or a sandbox against hostile code. The product still supplies
native system instructions and shell tools. The benchmark therefore cannot make
claims about a bare model served through the original HTTP harness.

## Metrics

Primary: public and held-out suite correctness. Secondary: observation characters
(including search and tree), source-view characters, actions excluding start but
including finish, rejected edits, and actual observation choices by file size.
Elapsed time starts at `start` and ends at final verification, excluding agent
startup/final prose and including scheduling delays. It is descriptive only.
API tokens, provider cost, reasoning tokens, exact model snapshot, and sampling
seed are not exposed by the native runner. Characters are not token estimates.

The previous pilot used line edits and lacked common search; do not interpret
differences between these datasets as an isolated effect of repository size.

## Run and inspect

Use the local Python executable at
`.runtime/python/cpython-3.13.15-windows-x86_64-none/python.exe` or Python 3.10+.

```powershell
python -B experiments/test_large_controlled.py
python -B experiments/large_controlled.py audit
```

`prepare` refuses to overwrite an existing dataset. Select a new dataset path
before generating another run. The task-specific `participant_prompt.txt` files
provide native-agent launch prompts. Keep `model="gpt-5.6-luna"`,
`reasoning_effort="low"`, and `fork_turns="none"` for matched replications.

Final artifacts include `summary.json`, `REPORT.md`, prelaunch fixture validation,
per-trial action/result logs, public/held-out rechecks, and source diffs.
